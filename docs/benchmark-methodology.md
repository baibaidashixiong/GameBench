# Benchmark 测试方法

## 模式

- Reproducible：固定种子、固定规模、Affinity、预热、重复次数和严格结果校验。
- Realistic：更大规模、动态任务强度和更接近引擎帧中的调度分布，但仍记录完整配置。

## 单次运行

1. 校验配置并生成确定性输入。
2. 执行预热阶段，不采样。
3. 记录重复样本的帧时间和线程时间。
4. 验证工作负载输出校验值。
5. 保存原始样本、配置、硬件和环境信息。

## 公平性

- 所有架构使用相同算法、数据规模和编译选项。
- `threads` 表示包含主线程在内的总执行参与者；1 线程由主线程闭环执行，多线程由主线程和 `N-1` 个 Worker 共同执行。
- 线程扩展性以结果中的 `thread_scaling_reference` 为基线；单进程 Job System 使用 1 线程，默认五进程组合使用 5 个总执行参与者。
- 不以厂商名称选择特殊代码路径。
- 拓扑不确定时不做性能推断。
- Vulkan No-Submit 与 GPU-backed 模式分开报告，GPU 时间不混入 CPU 综合分数。
- Synthetic 与真实引擎结果分开评分。

## 统计

报告中提供均值、中位数、P95、P99、P99.9 和最大值。主线程 CPU 时间、Worker 忙碌时间和总 CPU 工作均按每帧样本计算后取中位数；`scheduling` 块中的任务数和最后一次采样的 Worker 时间明确标记为 `last-measured-frame`。异常值保留在原始数据中；任何过滤规则必须显式记录配置和影响。

## 多进程

默认组合包含 1 个父协调进程和 5 个游戏工作子进程。子进程在预热阶段前启动并通过 READY 屏障确认；60 帧预热将启动开销排除在正式样本外，但 `launch_ms` 仍作为诊断保留。每帧由父进程向所有子进程发送任务并等待联合结果，墙钟时间包含进程间唤醒、Pipe I/O 和同步。

四个辅助进程的负载权重和进程数量是固定 Synthetic 配置，不是真实游戏 trace 采样。多进程结果标记为 `execution_domain: multi-process`，与单进程线程结果分开比较。
