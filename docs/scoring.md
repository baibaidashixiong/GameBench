# 评分说明

第一版评分只基于通过正确性校验的 Release 结果。单个工作负载报告原始时间与归一化吞吐量，不直接相加互不相关的 FPS。

线程扩展性：

```text
S(N) = T(base) / T(N)
E(N) = S(N) / (N / base)
```

`base` 写入结果的 `thread_scaling_reference`。单进程 Job System 工作负载通常以 1 线程为基线；默认五进程组合负载以 5 个执行参与者为基线。1 线程基线的 Job System 任务仍通过闭环队列提交和执行，因此包含调度设施本身的开销，但不包含跨线程唤醒和同步开销。v2 执行模型的旧结果不得与新基线直接比较。

综合分数必须由版本化的评分配置生成，并保存每项权重、输入结果版本和归一化基准。Synthetic 与 Engine 后端拥有独立评分域。Vulkan GPU-backed 的 GPU 时间、环境温度和频率只作为诊断，不进入 CPU 分数乘数。

未通过校验、缺少环境信息或版本不兼容的结果不得进入综合评分。

## 当前评分版本 1

每个工作负载和线程数输出两个透明指标：

- 吞吐：`实测操作数 / 采样中位时间`，单位为 operations/s。
- 线程扩展指数：相对同一结果中 1 线程中位时间的百分比，等价于 `S(T) * 100`。

不同工作负载的操作单位不同，因此 v1 明确设置 `comparable_across_workloads: false`，不生成跨工作负载总分。正式参考分数需要另行发布版本化参考机器数据和权重，不能使用单机结果临时拼合。

`execution_domain: multi-process` 的结果单独评分。父协调进程、主游戏子进程和四个辅助子进程的 CPU 时间分别记录；不把协调开销隐藏到主游戏 FPS 中，也不把多进程结果与单进程线程结果混成同一个绝对分。
